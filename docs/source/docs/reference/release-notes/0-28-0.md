# v0.28.0

## Behavior changes

### Rotation gate transpilers now keep the exact gate matrix (#598)

`RX`, `RY` and `RZ` have period 4π as matrices: `RX(θ + 2π) = -RX(θ)`. Three transpilers reduced angles modulo 2π, so they could flip the sign of the gate matrix (a global phase of -1). They now use 4π:

* `NormalizeRotationTranspiler` normalizes angles into `[0, 4π)` by default, instead of `[0, 2π)`. `cycle_range` now accepts any range whose width is a multiple of 2π.
* `FuseRotationTranspiler` reduces fused angles modulo 4π.
* `ZeroRotationEliminationTranspiler` no longer removes rotations near 2π, because their matrix is `-I`.

Transpiled angles and gate counts can differ from 0.27.0. To get the previous output (equal up to global phase), pass the old range explicitly:

```python
NormalizeRotationTranspiler(cycle_range=(0.0, 2 * np.pi))
```

### Old shot count keywords are accepted again, with a deprecation warning (#606)

v0.27.0 renamed the shot count argument to `shots` without a compatibility alias (#585). The old keywords `n_shots`, `measurement_cnt` and `shot_count` now work again in the places below. They emit a `DeprecationWarning` and will be removed in a future release.

* `sample()` of the Qiskit and Braket sampling backends, including the saved-data backends and the Qiskit Runtime primitive backend
* `sample()` of quantum states, and `sample(shot_count=...)` of `ImmutableQuantumCircuit` and `ImmutableParametricQuantumCircuit`
* The Qulacs vector state samplers, such as `create_qulacs_vector_state_sampler()`
* `sample_from_state_vector()`, `sample_from_density_matrix()` and their ideal variants, the sampler from `create_sampler_from_sampling_backend()`, and parametric samplers built with `create_parametric_sampler_from_sampler()` or `create_parametric_state_sampler_from_state_sampler()` (`measurement_cnt`)
* QURI Algo: `execute_qpe`, `analyze_qpe`, the QPE estimators, the Hadamard test estimator and the time evolution estimators

Samplers from `quri_parts.qulacs.sampler` that take a circuit, such as `create_qulacs_vector_sampler()`, and the sampler from `create_sampler_from_concurrent_sampler()` still accept only `shots`.

### The `quantinuum` extras now install the Nexus client (#614)

`pip install "quri-sdk[quantinuum]"` and `pip install "quri-parts[quantinuum]"` now install `quri-parts-quantinuum[nexus]`, which adds `qnexus`, `pytket` and `quri-parts-tket`. If you only need circuit conversion and the native gate transpiler, install `quri-parts-quantinuum` alone.

## Dependency changes

* `quri-parts-qiskit` now requires `qiskit>=2.2,<2.6` (#613). On Linux, importing Qiskit 2.6.0 before Qulacs fails with a static TLS error ([Qiskit/qiskit#17213](https://github.com/Qiskit/qiskit/issues/17213)).
* `quri-parts-itensor` now requires `juliacall>=0.9.32,<0.10.0` (#616). Older JuliaCall versions could crash the Python process with SIGSEGV when Julia shut down.

## New features

### Run circuits on Quantinuum devices through Nexus (#614)

`quri_parts.quantinuum.backend.QuantinuumSamplingBackend` submits sampling jobs through [Quantinuum Nexus](https://docs.quantinuum.com/nexus/) to Quantinuum systems (H-Series), their emulators and syntax checkers, and Nexus-hosted simulators.

```python
import qnexus as qnx
from quri_parts.quantinuum.backend import QuantinuumSamplingBackend

qnx.login()  # once per machine
backend = QuantinuumSamplingBackend("H2-1E")
job = backend.sample(circuit, shots=1000)
counts = job.result().counts
```

`QuantinuumSamplingJob.from_id()` recreates a job from its Nexus job id, so you can collect the results from another process, for example after an HPC batch job. Helios devices are not supported yet. See [Sampling on Quantinuum devices](https://quri-sdk.qunasys.com/docs/howto/running_and_simulating/quantinuum_sampling.html) for details.

### Readout error simulation (#610)

`quri_parts.core.sampling.create_readout_error_concurrent_sampler()` wraps any `ConcurrentSampler` and flips each measured bit independently. You give the probabilities `p0_to_1` and `p1_to_0` as one value for all qubits or one value per qubit. Wrapping a noise-free sampler simulates readout errors with a single state vector simulation per circuit.

```python
from quri_parts.core.sampling import create_readout_error_concurrent_sampler
from quri_parts.qulacs.sampler import create_qulacs_vector_concurrent_sampler

sampler = create_readout_error_concurrent_sampler(
    create_qulacs_vector_concurrent_sampler(), p0_to_1=0.01, p1_to_0=0.02
)
```

### Build `MolecularSystem` from PySCF objects (#599, #602)

In QURI Algo, `MolecularSystem.from_pyscf()` wraps an existing PySCF `Mole` or a converged mean-field object. Your SCF settings are kept, and a converged mean field is not run again. Unrestricted (UHF) mean fields are not supported yet.

`MolecularSystem` also gains:

* `hf_state`, `hf_energy`, `n_qubits` and `n_electrons`
* a `fermion_qubit_mapping` option (Jordan-Wigner by default)
* a `qubit_mapping` property, to decode sampled states with the same mapping as the qubit Hamiltonian

## Bug fixes

* Converting two- and three-qubit `UnitaryMatrix` gates between QURI Parts and tket could apply them to the wrong qubits, in both directions (#615)
* `MeasurementNoise` with `qubit_indices` was applied to every qubit (#601)
* Converting Qsub programs to QRET failed with "Reallocate symbol" when sibling subcalls wrote to aux registers (#600)
* The Qulacs vector samplers ignored `random_seed` when they switched to multinomial sampling for large shot counts (#610)
* The type stub of `ImmutableParametricQuantumCircuit.sample()` named the parameter argument `param` instead of `params`, so valid `params=` calls failed type checking (#607)

## Other changes

* `OpenFermionQubitMapping.inv_state_mapper` is faster when decoding many states. The results are unchanged (#609)
* `quri_algo.circuit_lib.qpe` now uses named registers, like the deprecated `quri_parts.qsub.lib.qpe` (#603)
* Documentation: the Qsub transpiler tutorial is now in the sidebar (#612), duplicate footnotes in the variational tutorial are fixed (#596), and the release notes for v0.26.3, v0.26.4 and v0.27.0 are added (#595)

## For contributors

* Lint CI now warns about missing docstrings on public modules, classes, functions and methods in the files that a PR changes (#597). The check does not fail the build yet.
